# Беклог

Тікети з цього плану вже заведені на дошці Jira. З цих файлів другу дошку не створюють.

| Файл                                               | Що це                                                       |
| -------------------------------------------------- | ----------------------------------------------------------- |
| [28_JIRA_BACKLOG.md](28_JIRA_BACKLOG.md)           | Груба нарізка плану на епіки і історії                      |
| [engineering/](engineering/00-project-overview.md) | Дрібніша локальна нарізка: епіки, тікети, залежності, дірки |

Порядок читання всередині `engineering/`:

1. `00-project-overview.md` — межі і що вже не так у старому огляді.
2. `06-mvp-scope.md` — що входить у MVP.
3. `09-gaps-and-unknowns.md` — що не можна додумувати.
4. `05-implementation-roadmap.md` і `04-dependency-graph.md` — порядок.
5. `tickets.md` або `03-master-backlog.md` — текст тікета, коли береш конкретний номер.

`tickets.csv` і `backlog.csv` — таблиці для імпорту. Вимоги з них не вигадують поверх markdown.

Описи в `doc/archive/jira-import/scripts/issue-desc/` плутають ключі Jira. Наприклад, локальний `KIN-126` там про пошук фільмів, а в `28_JIRA_BACKLOG.md` той самий ключ про реєстрацію. Джерело історії — дошка і `engineering/`, не ці файли.
