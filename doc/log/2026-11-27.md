## Виправлення refresh для парольних identities

- Джерело: live E2E KinVue Client, PR #19; браузер надсилав HttpOnly cookie, але refresh повертав 401.
- Причина: після ротації `TokensService` шукав лише legacy `AuthUser`; парольний signup створює `AuthIdentity`, а звичайний користувач може не мати `AuthUser`.
- Рішення: при refresh перевіряти стан `AuthIdentity`, якщо такий запис існує; активній identity без legacy role row видавати звичайний USER access token. Google `AuthUser` роль лишається джерелом admin scope; неактивні identities відхиляються.
- Перевірка: `pnpm --filter @kinvue/auth test:refresh` — 7/7; `test:auth-http` — 14/14; auth typecheck пройшов.
- Не зроблено: Server PR і повторний live E2E ще попереду; KIN-344 та Client PR #19 лишаються відкритими.
