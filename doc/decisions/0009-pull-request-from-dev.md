# 0009. Зміни йдуть гілкою від dev і через pull request

- Статус: прийнято
- Дата: 2026-10-26
- Джерело: чат 2026-10-26
- Замінено: немає

## Контекст

Агент може зробити всю роботу, сидячи на `dev`. Без окремої гілки і pull request рев'ю немає, а `dev` змішується з незакінченим.

## Рішення

Будь-яка зміна, яку агент віддає на GitHub, іде так:

1. Локальний `dev` збігається з `origin/dev`.
2. Нова гілка створена від `dev`.
3. Якщо файли вже змінені на `dev` або лежать у локальних комітах поверх `dev`, їх переносять на цю гілку до коміту. Локальний `dev` після цього знову збігається з `origin/dev`. Force push не використовують.
4. Коміт пушать на гілку і відкривають pull request у `dev`.

Прямий коміт або пуш у `dev` чи `main` не є здачею роботи. Без відкритого pull request завдання не завершене.

CI/CD як шлюз злиття ще немає. Його відсутність не причина пропускати pull request і не причина додавати пайплайн у тому ж завданні.

## Порушення

Пуш у `dev` або `main`. Коміт на `dev`, коли зміни мали бути на гілці. Закриття завдання без pull request. Force push, щоб «прибрати» коміти з `dev`.

## Наслідки

Навіть дрібна правка документації виходить окремою гілкою і pull request у `dev`.
