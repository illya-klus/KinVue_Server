# 0008. Цільовий план: три входи і межі сервісів

- Статус: прийнято
- Дата: 2026-10-26
- Джерело: чат 2026-10-26, пак `doc/design/`
- Замінено: немає

## Контекст

Рішення 0001–0006 зняті з коду, який уже є. Пак `doc/design/` — приблизний план, з якого зібрані тікети на дошці. Частина цього плану суперечить формулі «клієнт входить лише в gateway».

## Рішення

Цільова архітектура v1 — файли `doc/design/00`–`26`. Покрокова збірка — `doc/plan/`. Тікети — `doc/backlog/`. Дірки з `doc/backlog/engineering/09-gaps-and-unknowns.md` лишаються відкритими: агент не вигадує для них відповідь.

Зовнішні шляхи:

- HTTP API йде в gateway.
- WebSocket кімнат іде в Rooms, не через gateway.
- Байти відео йдуть через сховище і CDN, не через сервіси.

Межі:

- Auth володіє особою і токенами. Users — профілем і друзями. Movie — каталогом. Rooms — ефемерним станом кімнати, відтворенням, чатом і реакціями. Notifications — доставкою подій.
- Окремого Chat Service і окремого Streaming Service у v1 немає. Каркас `services/chat` не розбудовують у продукт.
- Код лишається в `services/*` і `packages/*`. Дерево `apps/` з плану не створюють, доки тікет прямо не переносить репозиторій.
- Веб-клієнт у цей репозиторій не додають без тікета, який кладе його сюди.

Поточний gRPC gateway → auth (0003) і поточні терміни JWT (0005) цим записом не скасовуються. Їх змінює тікет, який бере саме цей шматок, і нове рішення в `doc/decisions/`.

## Порушення

Проксити WebSocket кімнат або байти відео через gateway. Завести окремий Chat Service або Streaming Service. Закрити відкриту дірку з `09-gaps-and-unknowns.md` мовчки. Перейменувати `services/` на `apps/` попутно з іншим завданням.

## Наслідки

0002 більше не забороняє публічний WebSocket Rooms і CDN. HTTP API і далі входить у gateway.
