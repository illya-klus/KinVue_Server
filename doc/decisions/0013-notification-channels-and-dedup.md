# 0013. Канали сповіщень v1 і сховище дедуплікації

- Статус: прийнято
- Дата: 2026-10-26
- Джерело: чат 2026-10-26, KIN-93
- Замінено: немає

## Контекст

План пропонує in-app сховище, фейковий push і дедуп за `eventId`. Справжній вендор push у відкритих питаннях ще не обраний.

## Рішення

- Сповіщення в застосунку зберігають у PostgreSQL сервісу Notifications.
- Справжній push на пристрій відкладений. Локально і в v1 достатньо провайдера, який лише пише в лог.
- Дедуплікація за `eventId` живе в таблиці Notifications, не в Redis кімнат.
- Повтори: 2, далі DLQ. Повторне програвання DLQ — CLI.
- Вендор push цим записом не обирається.

## Порушення

Тримати дедуп у Redis кімнат. Обіцяти exactly-once доставку. Підключити реальний push-вендор без нового рішення.

## Наслідки

ADR-018 про два повтори лишається. Сховище сповіщень — окрема Postgres, не база auth і не Redis кімнат.
